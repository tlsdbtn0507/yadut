# GPT-6 작업 프롬프트: ThinkPad 로컬 대화 DB

아래 작업을 `/Users/sin-yusu/yadut` 저장소에서 수행해 줘.

## 목표

ThinkPad 서버에만 저장되는 SQLite 기반 대화 저장 기능을 구현한다. 현재 `codex/b-design` 브랜치의 B안 UI는 그대로 유지하고, 사이드바의 더미 이전 대화를 실제 저장 데이터로 교체한다. 외부 DB나 클라우드 저장소에는 대화·개인정보를 보내지 않는다.

## 작업 원칙

1. 먼저 루트 `AGENTS.md`를 끝까지 읽고 따른다.
2. 현재 작업 트리의 변경을 보존한 채 `codex/b-design`을 기준으로 새 브랜치 `codex/thinkpad-conversation-db`를 만든다.
3. 이번 작업에서는 DB와 그 연결에 필요한 최소 UI 변경만 한다. 색상, 레이아웃, B안 디자인은 다시 설계하지 않는다.
4. 구현 전 수정 파일과 데이터 흐름을 한국어 계획으로 설명하고 내 승인을 기다린다.
5. Python 표준 라이브러리 `sqlite3`를 우선 사용한다. ORM이나 새 DB 의존성은 추가하지 않는다.
6. 별도 요청 없이 커밋·푸시·배포하지 않는다.

## 필수 기능

- DB 파일은 ThinkPad 서버 로컬의 명시적인 데이터 디렉터리에 둔다. 저장소와 데이터 파일 경로를 분리하고 SQLite 파일은 Git에 포함하지 않는다.
- 앱 시작 시 안전하게 실행되는 버전 기반 스키마 초기화/마이그레이션을 제공한다.
- 최소 스키마:
  - `conversations`: ID, 제목, 생성 시각, 수정 시각
  - `messages`: ID, conversation ID, 역할(user/assistant), 본문, 생성 시각, 전송 상태
  - 첨부 메타데이터: 종류, 원본 이름, 로컬 파일 경로, MIME 타입
- 대화 생성, 목록 조회, 단일 대화와 메시지 조회, 메시지 추가 API를 ThinkPad FastAPI 서버에 구현한다.
- 최신 수정 순으로 목록을 반환하고 UI에서 `오늘`, `지난 7일`, 그 이전 기간으로 그룹화할 수 있는 ISO 8601 시각을 제공한다.
- 메시지 저장은 클라이언트가 생성한 `message_id`를 UNIQUE로 처리하여 재시도에도 중복 저장되지 않게 한다.
- 현재 스트리밍 응답 흐름을 보존한다. 사용자 메시지는 요청 수락 시 저장하고, assistant 메시지는 terminal `completed` 이벤트의 실제 결과만 저장한다. 실패 이벤트는 상태로 추적하되 가짜 assistant 대화를 만들지 않는다.
- 이미지/PDF 원본을 SQLite BLOB으로 넣지 말고 ThinkPad 로컬 파일로 저장한 뒤 DB에는 검증된 상대 경로와 메타데이터만 기록한다. 경로 순회(`..`)와 임의 절대 경로 접근을 막는다.
- Vercel 웹은 기존 인증 BFF를 통해서만 ThinkPad API를 호출한다. 브라우저에 ThinkPad 주소나 비밀 토큰을 노출하지 않는다.
- `project_web/src/components/YadutSidebar.tsx`의 더미 데이터는 실제 API 결과로 교체한다. 로딩·빈 상태·오류 상태를 최소한으로 제공하고 기존 대화 선택 시 저장된 메시지를 불러온다.
- 새 대화를 시작하면 conversation을 만들고, 홈에서 첫 메시지를 보내도 새 conversation에 연결한다.

## 향후 온톨로지 연동을 위한 설계

- SQLite에 저장한 대화 원문은 앞으로 구축할 아르커스 개인 온톨로지의 신뢰 가능한 원천 데이터로 사용한다. 요약문만 남기지 말고 원본 메시지와 첨부 메타데이터를 보존한다.
- conversation, message, attachment에 변경되지 않는 안정적인 ID와 UTC 기반 생성·수정 시각을 부여해, 미래의 온톨로지 노드와 관계가 원본 기록을 역참조할 수 있게 한다.
- 온톨로지 추출 파이프라인이 새 메시지만 증분 처리할 수 있도록 메시지별 추출 상태, 처리 버전, 마지막 처리 시각을 기록할 최소 확장 지점을 설계한다. 재시도 시 동일 메시지가 중복 반영되지 않아야 한다.
- 미래에 추출할 인물·장소·일정·선호·습관·경제정보 등의 사실은 반드시 출처 message ID, 신뢰도, 생성 시각, 수정 시각을 연결할 수 있어야 한다.
- 대화 저장 계층과 온톨로지 저장 계층을 강하게 결합하지 않는다. 별도 온톨로지 서비스가 저장 완료 이벤트 또는 명시적인 조회 인터페이스를 통해 대화를 읽고 동기화할 수 있도록 경계를 정의한다.
- 원본 메시지가 수정되거나 삭제되면 그 메시지에서 파생된 온톨로지 사실을 찾아 갱신·무효화·삭제할 수 있도록 provenance(출처 추적) 구조를 고려한다.
- 이번 작업 범위는 SQLite 대화 저장과 미래 온톨로지 연동에 필요한 ID·메타데이터·인터페이스 설계까지다. 온톨로지 엔진, 지식 그래프, 임베딩 생성 자체는 구현하지 않는다.

## 개인정보 및 운영 안전

- SQLite 연결마다 foreign key를 활성화하고 필요한 인덱스를 둔다.
- SQL은 전부 파라미터 바인딩을 사용한다.
- 로그에 대화 본문, 개인정보, 토큰, 첨부 원문을 남기지 않는다.
- DB와 첨부 디렉터리는 환경변수로 경로를 바꿀 수 있게 하되 안전한 로컬 기본값을 제공한다.
- WAL, busy timeout, 트랜잭션 경계를 설정해 단일 사용자 환경의 동시 요청에 안전하게 만든다.
- 백업은 이번 구현 범위에서 자동화하지 말고, 일관된 백업 방법과 복구 절차만 문서화한다.
